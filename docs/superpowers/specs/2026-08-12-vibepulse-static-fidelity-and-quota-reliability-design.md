# VibePulse Static Fidelity and Quota Reliability Design

## Outcome

Correct the two failures found in the first physical/static install:

1. replace the visibly broken three-layer Codex mark with one source-derived,
   transparent indexed image; and
2. make Claude and Codex quota selection survive temporary source loss without
   confusing named model limits with the provider's general weekly limit.

The icon must read as the real blue-gradient Codex cloud and white terminal
glyph on the black AMOLED background, without the source app icon's white
rounded-square plate. The data path must show the most recent authoritative
quota for its exact identity and reset cycle, never a convenient but unrelated
number.

This is a focused correction to the existing static VibePulse design. It does
not authorize motion, change attention copy, alter quota geometry, add a new
quota page, or claim a physical AMOLED pass.

## Observed failures and root causes

The observations below came from the live Mac service and installed static
build on 2026-08-12:

- Claude's model-week fields were `null`. The tokenserver root diagnostic was
  `token_expired_02:40`; no active Claude Code child process exposed a refreshed
  process token. The ESP parser and LVGL renderer did not drop the value.
- Codex `WEEKLY` showed `0%`. The newest rollout record was actually the named
  `GPT-5.3-Codex-Spark` limit, with its own limit identity and 19 August reset.
  The general Codex weekly limit was `46%`, with a different identity and 18
  August reset. The scanner selected the newest file without classifying
  `limit_name`, so the named model quota incorrectly replaced general weekly.
- The current content-free history contained no Claude model-week sample, so
  no truthful Fable value could be recovered for this incident.

These facts rule out UI-label, font, Wi-Fi and ESP parsing as the primary
causes. The fix belongs at quota identity, persistence and presentation
boundaries.

## Source of truth

`components/app_tokens/assets/source/codex-icon.png` is the sole visual source.
The generator must derive all retained cloud, gradient, chevron, and underscore
pixels from that file. It must not redraw or approximate the Codex shape.

The white rounded-square app plate is deliberately excluded. The transparent
crop is the colored cloud's bounding box, while the two enclosed white terminal
components remain exactly aligned with the cloud.

## Asset representation

Generate a single LVGL `LV_COLOR_FORMAT_I4` image for each native render size:

- 112 x 112 asset for the large attention renderer;
- 32 x 32 asset for the quota-page provider header.

Palette index zero is transparent. The remaining fifteen entries must include
one exact white entry for the terminal glyph and a deterministic quantization
of the source blue gradient. Before quantization, use alpha-aware high-quality
downsampling and remove the white app-plate fringe from the transparent cloud
edge. Both assets are regenerated by the pinned
`tools/agent_assets/build-agent-images.py` workflow; generated C is never
hand-edited.

One composited I4 asset replaces the current cloud-plus-two-A8-mask stack. This
removes inter-layer alignment and recolor failure modes and reduces stored image
data relative to three full-size layers.

## Rendering contract

The large attention icon remains in the approved 112 x 112 box at `(184, 89)`,
centered inside the existing 136 px provider ring. It is one LVGL image object,
drawn at 1:1 with no LVGL stretch transform. This avoids the indexed-image
strip-decoder transform path used by the target's current LVGL configuration.
It must not show a white plate,
rectangular background, detached glyph, clipped cloud, or pixels outside the
box.

The quota-page header uses the generated 32 x 32 composited asset in its current
position. Claude rendering, all provider colors, the Codex ring and outline
color `#6F78FF`, text, touch behavior, event policy, and layout remain unchanged.

## Quota identity contract

The tokenserver must classify rate-limit snapshots before choosing a display
value:

- Codex `WEEKLY` accepts only an unnamed/general weekly quota.
- A non-empty `limit_name`, such as `GPT-5.3-Codex-Spark`, is a named model
  quota. It must never replace general `WEEKLY`, even when it is newer.
- Stable source identities and reset timestamps distinguish simultaneous quota
  cycles. The implementation may hash a source identity for local cache keys,
  but must not expose raw account, organization, limit or credential values to
  the ESP, logs, captures or tests.
- Named Codex quotas remain unrendered until a separate page is explicitly
  designed. This batch does not add a Spark page.
- Claude model-week uses only the model-specific header bucket and its trusted
  source label. Active chat model names must not manufacture quota identity.

Scan order may determine freshness within one exact identity; it must not
determine which identity is semantically `WEEKLY`. If no authoritative general
Codex weekly snapshot exists, the live value is unavailable and cache policy
below decides whether a stale value can be shown.

The Codex scanner remains bounded and asynchronous. It examines at most the 20
most recently modified rollout files and at most the existing one-megabyte tail
budget per file, collects only structurally valid rate-limit events, and then
selects the newest unexpired unnamed/general weekly observation. It does not
stop merely because it encounters a named, expired, or unclassifiable record.
Named Codex observations are classified and excluded from the rendered general
scope; persisting them is not required until they have a designed consumer.
Current general identities remain isolated. This supports an intentional
account/context switch without merging percentages or carrying one identity's
cache into another.

## Wire and ESP provenance contract

The existing nullable percent/reset/label fields stay backward compatible.
Contract v2 adds optional booleans, defaulting to false when absent:

- `claudeWeekStale`
- `claudeModelWeekStale`
- `codexWeekStale`

`true` means the paired percent/reset/label came from an unexpired persistent
last-known-good record because the authoritative source was unavailable.
`false` means the paired numeric value is fresh. A missing numeric value must
have stale false. Source diagnostics such as `oauth_expired` remain on the Mac
root endpoint and are not sent to the display.

The C token model stores provenance beside each `tk_limit`; the parser validates
that stale is boolean and cannot accompany a missing percentage. The presenter
passes provenance through. LVGL only renders the resulting `LIVE`, `STALE` or
`NO DATA` state and never infers it from HTTP success, packet age, labels or
agent activity. Packet/network staleness still has priority over quota-source
provenance because it means the display cannot establish current server state.

## Component boundaries

- `tools/tokenserver/tokenserver.py` classifies Claude and Codex source
  snapshots and publishes explicit provenance.
- A focused content-free quota-cache module owns validation, atomic persistence,
  reset expiry and identity isolation. Usage history remains responsible for
  deltas and forecasts; it is not overloaded as the source-of-truth cache.
- `tokens_parse.c` validates the backward-compatible wire fields and stores
  provenance; `usage_presenter.c` chooses display state; `usage_screen.c`
  renders that state.
- The agent-status endpoint and completion queue remain independent. Agent
  activity cannot make a stale quota fresh.

## Last-known-good quota cache

Persist a small, content-free quota snapshot atomically on the Mac. Each record
contains only:

- provider and canonical internal semantic scope (`general_session`,
  `general_weekly`, or `model_weekly`);
- a privacy-safe identity key;
- percentage;
- reset timestamp/cycle;
- trusted display label when the source supplies one; and
- observation time.

No prompt, response, command, project, model activity, credential, raw limit
identifier, account identifier or organization identifier may be stored.

The cache rules are:

1. A fresh authoritative sample replaces the matching cached record.
2. A temporary source failure, including expired Claude OAuth or absent active
   Claude process, may reuse the newest cached record only while its reset is
   still in the future.
3. A cached record must never cross its reset timestamp or be reassigned to a
   different quota identity.
4. A valid fresh decrease is accepted as authoritative; it must not be rejected
   merely because it is below the cache.
5. A named Codex model cache must never satisfy general Codex `WEEKLY`.
6. If no safe record exists, percent remains unavailable; no fallback number is
   inferred from another quota.
7. Live versus cached origin is explicit in the wire contract so the ESP can
   render `LIVE` or `STALE` truthfully. A successful HTTP response containing a
   cached value is not live quota data.

The cache loads on tokenserver start and is updated using write-fsync-replace.
Malformed, partial, non-finite, out-of-range, expired or schema-incompatible
records are ignored without discarding other valid records.

## Missing-data presentation

The quota name and numeric availability are independent:

- When the trusted cached Claude label is `FABLE · WEEK`, retain that label and
  its unexpired cached value with `STALE`.
- When the source is unavailable and no prior trusted model label/value exists,
  show the stable page identity `FABLE · WEEK`, a large dash, and `NO DATA`.
  The fixed page name identifies the product slot; it does not invent a quota
  percentage.
- General Claude and Codex pages follow the same numeric rule: unexpired cache
  renders with `STALE`; no safe value renders as a dash with `NO DATA`.
- Reset and today's delta are shown only when they belong to the same cached or
  live reset cycle. Missing delta never becomes zero.

The status has one reserved location and priority: `NO DATA`, then `STALE`,
then live agent context. It must not add a rail, row, card or automatic page.

## Verification

The asset generator tests must prove:

- both generated images have one I4 descriptor with the requested dimensions;
- palette index zero is transparent and an exact white glyph color exists;
- the generated asset contains substantial source-blue and white regions;
- no separate Codex chevron or underscore descriptors remain;
- generation is deterministic and derived from the canonical source PNG.

The host data tests must prove:

- a newer named Spark snapshot cannot replace an older-but-current general
  Codex weekly snapshot;
- freshness is selected within, not across, exact identities;
- multiple concurrent named and general reset cycles remain separate;
- last-known-good Claude and Codex values survive process restart and temporary
  source failure as `STALE`;
- cached data expires exactly at reset and never crosses into the next cycle;
- fresh decreases and new reset cycles replace old cache truthfully;
- malformed persistence, atomic-write failure and missing cache fail safely;
- raw identifiers, credentials and user content are absent from persistence,
  JSON responses, logs and fixtures;
- live/stale/no-data provenance reaches the C parser and presenter without the
  LVGL renderer inferring source health.

The exact 480 x 480 LVGL raster tests must prove:

- the attention icon stays inside `(184, 89, 296, 201)`;
- pixels around the cloud remain black rather than white app-plate pixels;
- the cloud retains a substantial blue-gradient area and both white terminal

- the rendered silhouette is non-rectangular and visually distinct from the
  previous broken three-layer capture;
- the small quota-page Codex icon uses the same composited source asset;
- Claude attention and quota captures remain unchanged outside generated
  capture metadata.

## Attention-count truth

The static attention view is an attention signal, not a permanent todo list.
Claude or Codex `waiting` and `error` records older than two hours become
`unknown` at the Mac source until a new event refreshes their observation time.
The existing two-minute working lease remains unchanged.

`N CHATS WAITING` and the equivalent error copy count only jobs from the same
provider as the attention event. A Claude banner never includes Codex jobs, and
vice versa. Counting is intentionally not filtered per project in this batch;
that remains an open product decision.

Quota-page agent context treats `waiting` and `error` as active only while the
agent-status packet itself is within the existing 120-second lease. A dead
agent feed therefore cannot claim active chats forever while quota data keeps
arriving. The wire format does not change.
